What this report answers: for each screen, can the user Create, View, Edit and Remove what they should be able to? Where something is missing, is it missing only on the screen (the API already exists), missing everywhere, or present but broken? It also flags places where a hard Delete would be the wrong answer and a cancel, deactivate or archive is needed instead.

Headline: no screen is missing Create or View outright. The real gaps are Edit and Remove/Deactivate on secondary records, several buttons that silently fail or do less than they say, and status changes (cancel, complete) that don't carry their side effects such as refunds, queue tokens or notifications.

    Notes on the codebase

    Database: the app runs on SQLite via node:sqlite (db/index.js), not MySQL. database/schema.sql is stale — it predates migration 014 (still has the old per-hospital token index and uq_schedule_slot), so a DB built from it would differ from one built by npm run db:setup.

    Wiring script: scripts/check-api-wiring.py reports the Doctor dashboard, analytics and earnings APIs as unwired, but they are called from components/doctor/DashboardView.js and app/doctor/earnings/page.js (template-string URLs the regex misses). The Admin QR PNG/poster downloads are also wired. The only genuinely unused route is PATCH /api/doctor/schedule/[id].

    Permissions: FINANCE, SUPPORT and OPERATIONS roles are defined in config/permissions.js, but no screen or API can create a user with those roles (see X1).
